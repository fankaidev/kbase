当 Agent 开始执行真实工作，模型本身并不是唯一需要解决的问题。更现实的约束是：**它需要什么样的计算环境，才能真正使用现有的软件完成任务？**

这是 Computer Use 逐渐受到关注的原因。过去，开发者更倾向于通过 API、Function Calling 或 MCP，把软件能力拆解成模型可以调用的工具。但这种方式天然受制于软件开放程度。大量企业内部系统、桌面软件和专业工具并没有完整 API；而 Blender、Unreal、CAD 等应用又依赖特定操作系统、GPU 和本地运行环境。

对于这些场景，最通用的接口其实不是 API，而是**一台可以被完整操作的电脑** 。

近日，a16z 宣布领投远程计算公司 Phaze 875 万美元 Seed 轮，Indie、NextView Ventures、Makers Fund 和 Lerer Hippeau 参与。公司没有披露本轮估值、收入或客户数量。Phaze 由 Benjy Boxer 和 Chris Dickson 创立，两人此前共同创办 Parsec，并于 2021 年以约 3.2 亿美元出售给 Unity。a16z 也是 Parsec 的早期投资者之一。

这一次，他们重新做远程桌面，但目标已经从"让人远程使用电脑"，转向了一个更大的问题：**让人和 Agent 都能按需使用远程计算机。**


**0** **1**

**API 之外，Agent 正在获得 Computer**


过去几年，Agent 基础设施的一条主线，是把软件能力标准化。

搜索变成 API，数据库变成 Tool，浏览器变成 Browser Agent，企业软件则通过插件或 MCP 接入模型。这套架构的优势很明确：执行路径清晰、权限容易控制，也比模拟鼠标键盘更加高效。

但它存在一个结构性限制：**API 只能覆盖软件愿意开放出来的能力。**

Computer Use 采取了另一种思路。OpenAI 的 Operator、Anthropic 的 Computer Use，以及微软针对 Windows 的相关 Agent 能力，都在尝试让模型直接理解屏幕、操作鼠标和键盘。

对模型而言，软件不再必须提供一个专门的 Agent API。只要人能够使用，模型理论上也可以通过同样的界面使用。

因此，Agent 与软件之间的接口正在从"调用功能"逐渐扩展到"使用计算机"。

![](https://cubox.pro/c/filters:no_upscale()?imageUrl=https%3A%2F%2Fmmbiz.qpic.cn%2Fsz_mmbiz_png%2FA8dXHUIB8duuMW0t77LibjQagfkOweJbhESyE9v7Anicu7kYUfysUSic1pJXkVslzWGwTT1SfyAGtle2LoOsnKjOsUvkjLMXTLBibZogwwCxH1E%2F640%3Fwx_fmt%3Dpng%26from%3Dappmsg%26watermark%3D1%23imgIndex%3D2)

这并不是 API 会被淘汰。对于确定性任务，API 依然是成本最低、效率最高的方式。

真正发生变化的是：**Computer 开始成为 API 覆盖不到的通用执行层。**

而 Phaze 所在的位置，正好是这一层。


**02**

**Phaze 想做的，其实不是传统意义上的远程桌面**


从产品形态看，Phaze 仍然是一款 Remote Desktop。它针对的是低延迟、图形密集型工作负载，包括 3D 设计、工程、游戏开发等场景，并强调高帧率、多显示器、色彩准确度以及 GPU 工作负载。

但公司的商业逻辑并不是"远程办公还有增长空间"，Phaze 更关注的是一个长期存在的企业 IT 问题：**昂贵的 Workstation 并没有得到充分利用。**

NextView Ventures 在投资 Phaze 时给出了一个很具体的案例：一家大型制造企业可能拥有约 3 万台工程工作站，每台成本超过 1 万美元，仅硬件投入就超过 3 亿美元。但这些机器并不会全天候处于满负荷状态。

传统架构下，一台工作站通常绑定一个员工。员工下班后，机器基本闲置；另一名员工需要计算资源时，却可能还要采购新的设备。

Phaze 希望把这种"设备所有权"转化为"计算资源使用权"。工作站可以部署在办公室、数据中心或云端，员工通过网络访问，Agent 也可以在需要时获得一台机器。任务结束后，资源重新回到池中。

因此，Phaze 真正想做的是 **Workstation Infrastructure** ：把过去属于个人的高性能计算机，变成企业可以调度和共享的计算资源。

这与云计算早期解决的问题非常相似。云计算把服务器从"每家公司自己购买"变成了可以按需调用的资源；Phaze 则试图把 Workstation 从"每个人一台"，变成"人和 Agent 都可以按需使用"。


**03**

**Agent 为什么会放大这个需求？**


如果只有人类员工，这个市场的增长逻辑其实并不新鲜，真正改变需求结构的是 Agent。

一个工程师通常只有一台工作站，但未来一个工程团队可能同时运行多个 Agent：一个负责测试代码，一个负责执行渲染任务，一个负责监控设备，另一个负责处理 IT 问题。

这些 Agent 并不一定需要独立购买一台物理设备，但它们需要独立的执行环境。

这意味着企业未来配置计算资源时，衡量单位可能不再只是"员工数量"，而是**同时运行的数字劳动力数量** 。

这也是 Phaze 与普通 Remote Desktop 产品最大的区别。

传统远程桌面解决的是"人在哪里访问电脑"；Phaze 更关心"谁在使用电脑，以及这台电脑能否被动态分配给不同的任务"。

如果这一模式成立，Agent Infrastructure 的边界也会发生变化。

过去，开发者关注的是 Model Serving；后来增加了 Sandbox、Runtime、Browser 和工具调用。对于需要运行专业软件的 Agent，最终还需要一个完整的 Operating System 和 GPU 环境。

换句话说，Agent 不只是需要"知道怎么做"，还需要一个地方**真正把事情做完** 。


**04**

**为什么是这支团队？**


Phaze 最值得关注的一点，是它并不是一支第一次进入这个领域的创业团队。

Benjy Boxer 和 Chris Dickson 在 2016 年创办 Parsec，最初解决的是游戏和图形应用的低延迟远程访问问题。

Parsec 的技术难点并不是简单的视频串流，而是在远程环境中维持接近本地的操作体验：低延迟输入、高质量画面、GPU 加速、3D 应用以及复杂网络条件下的稳定连接。

2020 年，Parsec 完成 2500 万美元 Series B，由 a16z 领投；当时公司累计融资约 3300 万美元。2021 年，Unity 宣布以约 3.2 亿美元收购 Parsec。

对于 Phaze 来说，这段经历的重要性不只是"创始人做过一家成功公司"。

Parsec 已经证明了一件事：**当 GPU 计算和专业软件越来越集中在远端时，用户仍然需要一种接近本地的交互方式。**

区别在于，Parsec 的主要用户是人，而 Phaze 面对的是一个新的计算主体------Agent。

a16z 再次投资这支团队，本质上也是在押注同一个底层能力在新一轮计算范式中的价值：把远端计算资源以足够低的延迟交给使用者。


**05**

**875 万美元只是开始，真正的问题还没有答案**


当然，Phaze 的方向并不是没有风险。

首先，Computer Use 目前仍然存在可靠性、延迟和安全问题。能够通过 API 完成的任务，没有必要绕一圈去操作 GUI；而涉及高价值操作时，Agent 的一次错误点击可能造成比 API 调用更严重的后果。

其次，Phaze 并不直接提供 GPU、Workstation 或专业软件许可证。企业仍然需要承担这些基础成本。Phaze 能够捕获的价值，主要来自连接、管理、调度以及资源利用率提升。

更重要的是，公司目前并未公开收入、客户数量和估值，因此很难仅凭 875 万美元融资判断商业化进展。

但这笔 Seed 轮融资依然值得关注，因为它押注的是一个正在形成的基础设施层。

过去的企业计算，是"一个人配一台电脑"；云计算之后，变成"一个人按需调用计算资源"；而 Agent 进入生产环境之后，可能进一步变成：

**人和 Agent，共同调用一个可调度的计算资源池。**

这也是 Phaze 真正值得关注的地方。AI 基础设施过去最受关注的是 GPU、数据中心和模型。随着 Agent 从聊天窗口进入真实的软件环境，竞争的边界正在继续向下延伸------从模型到 Runtime，从 Runtime 到 Computer。

Phaze 想解决的并不只是远程桌面，它真正押注的是：**当 Agent 开始像人一样使用软件，一台电脑本身，也会成为 AI Infrastructure。**
