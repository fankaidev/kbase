> TL;DR：Claude Duet 的差异不在"也能后台干活"，而在于它面向专业人士和小企业主，把 Claude 已有的记忆、Skills 与连接器直接变成主动工作能力，并用独立分类器约束敏感信息流向。Grok Bot 更像多 Agent 团队，Muse 面向大众生活目标，Dots 则贯通 ChatGPT、Codex 与 Work。Duet 的优势是工作上下文迁移和审慎行动，不是全能：它仍处研究预览，数小时才巡检一次，不能查看浏览器，后台运行还共享 Claude 套餐额度。

## Duet 的"个人"，首先是一份工作的上下文

Anthropic 于 2026 年 10 月 22 日开放 Claude Duet 研究预览候补，首批面向美国 Pro 和 Max 用户。它虽然被归入 personal agent，官方目标用户却明确是专业人士和小企业主：晨间简报汇总已连接应用里的重要事项，白天发现需要处理的异常，用户也可以在一个持续对话里交代排会、财务预测、数据仪表盘、原型乃至 Web 应用开发。\[1\]

这使它与"生活秘书"有所区别。Duet 的基础不是重新填写一轮偏好，而是继承 Claude 账号已有的 memory、Skills 和 connected apps；任务在带浏览器的云端 VM 中运行，离开应用也能继续。它要找的是已经在 Claude 里积累了工作方法、文档处理和业务连接的人，把这种上下文从"回答问题时调用"变成"持续推进工作时调用"。Dots 同样不是 Codex 的一个模式，而是横跨 ChatGPT、Codex 和 ChatGPT Work 的个人 Agent 层，可以把任务交给后两者执行。\[1\]\[7\]

## 四款产品，分歧不在会不会干活

四者都有持久运行、应用连接、主动提醒和人工批准，真正的差异是 Agent 的组织单位及默认边界。

|       产品        |       主要组织方式       |                      更鲜明的机制                      |                   当前边界                    |
|-----------------|--------------------|--------------------------------------------------|-------------------------------------------|
| **Claude Duet** | 一个持续对话，服务个人工作      | 继承 Claude 记忆、Skills、6000 多个连接器；Opus 5.5；敏感信息外发检查 | 美国候补预览；数小时巡检；不可看浏览器；共享套餐额度                |
| **Grok Bot**    | 多个有角色和独立记忆的 Bot    | Bot 间群聊、交接与协调；定时或事件触发 Routines；可演示流程让它学习         | 同一账号的 Bot 共用云电脑，文件、浏览器会话和命令行凭据跨 Bot 可见    |
| **Muse**        | 面向大众生活目标的单一助手      | WhatsApp 入口；每人独立 Secure VM；系统级 Sentinel 审核联网动作   | 美国推出；大部分功能免费；Confidential VM 仍是后续计划       |
| **Dots**        | 一个可命名的 primary dot | GPT-6 Astra；4000 多个应用；可检查云电脑，也可连接个人电脑；主动研究使用只读工具 | 特定市场开放；多 dot 团队仍是未来方向；Codex 和 Work 沿用各自额度 |

Grok Bot 的重点是"组织"：销售、运营、工程等角色各自保存记忆和 Routines，群聊提供项目共享上下文，协调型 Bot 负责分派工作。它适合并行职责清晰的小团队，但角色隔离不等于安全隔离，官方明确提醒不要把不同 Bot 当作权限边界。\[3\]\[4\]\[5\]

Muse 则把消费级隐私架构放到台前。独立 VM 保存 Agent、数据和凭据，另一个 Sentinel 在系统层审查外发动作；发送邮件、购买前询问用户，交互数据不进入 Meta 广告系统。它还接入 WhatsApp、Link 一次性卡和购买保障，明显瞄准购物、出行、健康与家庭协调，而非先做专业工作台。\[6\]

Dots 位于两者之间：一个主 Agent 跨设备保持上下文，主动研究阶段只读，执行时再按内置或自定义规则请求批准。它的生态优势是 ChatGPT 的日常入口与 Codex、Work 的执行能力可以接续，云电脑还能打开检查；这比 Duet 当前"不能展示浏览器"的状态更透明。\[7\]\[8\]

## Duet 的优势，是把"谨慎"做成系统机制

Duet 最值得关注的安全增量，不只是"支付前点一下批准"。动作分类器在执行模型之外检查操作是否符合用户意图，降低网页或邮件中的隐藏指令直接改变审批结果的风险；密码、Cookie 和登录 token 也不进入模型所在机器，而由隔离的浏览器或代理注入。发送、支付、签署、删除等重要动作按规则展示目标、内容和收件人，等待人工决定。证券交易和账户间转账即使获批也不开放。\[1\]\[2\]

第二层是信息流向控制。个人 Agent 读邮件、财务和业务系统后，风险不仅是"做了未经授权的动作"，还包括把合法读到的信息发给不该收到的人。Duet 用独立分类器把信息分为"永不分享"和"获得同意才可分享"：完整卡号、政府证件号码等即使用户要求也不发送，健康和财务信息则需要明确同意。这是它与只强调动作审批的产品叙述之间最实质的差别。\[2\]

![](https://cubox.pro/c/filters:no_upscale()?imageUrl=https%3A%2F%2Fmmbiz.qpic.cn%2Fmmbiz_png%2FTa2h2oOxYtLKGFg5DtNc6Pg0CXicSgltzJLrnZ344UTC66lBOP2AOlAiboBzEpsEKSH7t2jDuWrFvfYFhs56GXBr2KAF4O4brVvpFz7gNtx2c%2F640%3Fwx_fmt%3Dpng%26from%3Dappmsg%23imgIndex%3D2)

不过，这些图说明设计边界，不证明实际安全性已经优于 Muse 或 Dots。Anthropic 也没有提供四者可直接对照的任务成功率。6000 与 4000 的连接器数量同样不能单独推出覆盖质量优势，真正影响体验的是目标应用是否可用、授权粒度和失败恢复。

## 它并不更"时刻在线"，优势仍有使用成本

Duet 的主动性更像低频值守，而非持续盯屏：官方称它每隔数小时检查连接账号，以避免过快耗尽额度。晨间简报和异常发现因此适合"今天最该处理什么"，不等于实时告警。研究预览还与 Claude 其他功能共享套餐额度，后台检查和大型任务都会消耗它；Grok Bot 则把 Bot 用量与原有 Grok、Cursor 套餐分开，Dots 的 ChatGPT 对话与 Codex、Work 用量也有不同口径。\[1\]\[3\]\[7\]

因此，Duet 当前最有说服力的人群，是已经把工作上下文放进 Claude、需要一个入口统一跟进邮件、客户、账务和文档的人。需要多角色并行，Grok Bot 的产品模型更完整；需要消费级生活服务和独立安全 VM，Muse 更直接；需要观察云桌面或衔接 Codex，Dots 更顺手。Duet 的潜力在于"懂既有工作、少打扰、对信息外发更克制"，但它是否真能以更少提醒换来更高质量的委托，仍要等研究预览中的独立使用证据。
