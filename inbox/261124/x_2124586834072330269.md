# 03. Hire - the team charter and role prompts

**A child agent starts with your prompt and nothing else.** It does not see the parent's history.

GILD found this out running research agents in T3 Code and wrote the rule down: write the child's prompt as a complete brief.

So the team gets two things: a charter file every agent reads, and a brief format every handoff uses.

- **3.1 **The charter: TEAM.md in your repo root

Claude Code, Codex, Antigravity and Grok Build all read project instruction files (Grok Build lists AGENTS.md support on [x.ai/cli](https://x.com//x.ai/cli)).

Put the team rules in one file and reference it from each:

python*# TEAM.md · read this before any task*

*## Roles*
- Lead (Fable 5.2): writes SPEC.md, splits work, takes the hardest slice.
- Builders (Opus 5.5): one slice each, one worktree each.
- Playtester (GPT-6.2 Astra): read-only. Reports bugs, never fixes them.
- Copywriter (Gemini 4 Neon): docs/, README.md, CHANGELOG.md, src/i18n/ only.
- Dispatcher (Grok Bot): files tasks. Never merges, never deploys.

*## Rules*
- Every handoff uses the BRIEF format below.
- A task is done only when its DONE WHEN check passes.
- Max 3 review rounds. Max 4 agent-to-agent handoffs without a human.
- Never touch .env*, migrations, or CI config without asking the human.

*## BRIEF format*
BRIEF FOR / ROLE / GOAL / CONTEXT / DONE WHEN / DO NOT / RETURN

- **3.2 **The brief: seven fields, every time

pythonBRIEF FOR: @<model>
ROLE:      <lead | builder | playtester | copywriter>
GOAL:      <the outcome in one sentence>
CONTEXT:   <files, decisions made, link to SPEC.md>
DONE WHEN: <a test passes, a command returns 0, a checklist is true>
DO NOT:    <files to leave alone, commands never to run>
RETURN:    <exactly what to report back>

- **3.3 **The four role prompts

pythonYou are the tech lead. Read TEAM.md first. Do not write feature code yet.

Task: <feature>
Acceptance test: <how I will know it works>

1. Read the codebase. Write SPEC.md: goal, files touched, risks, test plan.
2. Stop and wait for my approval of SPEC.md.
3. Split the work into slices that touch different files.
4. For each slice, use delegate_task to start a builder on @opus in its own
   worktree, with a full BRIEF.
5. Take the hardest slice yourself.
6. When builders finish, delegate a read-only review to @astra with the diff.
7. Fix what it finds. Stop after 3 review rounds and report.
8. Delegate README, CHANGELOG and UI copy to @neon last.

Report: slices, owners, test results, open risks.

# 05. Playtest & ship - cross-family review, PR from your phone

**A reviewer from the same model family shares the builder's blind spots.**

That is the whole reason Astra is on this team. The best public numbers come from GILD, who run Opus and Astra on each other's work inside T3 Code:

[Image](https://x.com/0xCodez/article/2124586834072330269/media/2124571483145916416)

Two rules from the people running this:

- **Cap review loops at 3 rounds.** After that, it is a human call (GILD).
- **Read-only is a promise, not a lock.** Smaje tells reviewers to read, not edit, "because nothing enforces it." Say it in the prompt and keep the reviewer on Supervised.

# 06. Go 24/7 - Grok Bot, schedules and webhooks

**Everything so far starts when you sit down. Step 06 makes the team start without you.**

Grok Bot is xAI's standing agent. It runs on its own cloud computer, signs into your existing tools and websites, works continuously, and messages back when it needs approval.

It shipped as a beta on August 11 and as Grok Bot 1.0 on November 11, with shared Team Bots in Slack and Teams.

Inside this team it is not a coder. It is the **dispatcher**: it watches the places work comes from, and files clean tasks into T3 Code.

- **6.1 **Connect Grok Bot to T3 Code over MCP

T3 Code runs an MCP server for "outside agents". Per the docs, any agent that supports remote MCP servers over HTTP with OAuth can connect, and hosted agents must use the T3 Connect address.

1. In T3 Code: **Settings → Environments** → environment menu → **Copy MCP URL** (with T3 Connect turned on, so a cloud bot can reach it)
2. In Grok Bot: add a remote MCP server with that URL and choose OAuth
3. Approve the sign-in on T3's page and choose **Supervised**, not Full access
