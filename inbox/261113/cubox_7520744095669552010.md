## 摘要

谷雨的年终「被打脸」清单。

* **积累可能是累赘。** 可以想象，AI 写 infra 和 recipe 总有一天超过人，到那时大模型公司攒下的那套可能反成包袱，NeoLab 随时能丢。他「瞎预测」明年可能有 RSI 公司的最强模型，至少是前沿模型。

* **搭好的 pipeline，不需要了。** 公司刚成立时花了几个月解决 computer use 的可靠性，现在让模型自己实现，很快。memory notes 的上限，他也承认低估了。

* **长程不是一件事干很久。** 是会计从菜鸟变成老员工的那几个月、一两年。他们的 benchmark，100 道题要连着做。

* **AI 是数字世界的机械。** 机械来了，强壮不那么重要了；AI 来了，轮到脑力。十年后教授的社会地位可能不如夜店男模。学术评价体系在他看来已经崩塌，一年半没投论文。

* **灭火器和砖头。** 学术上从不拿锤子找钉子，创业后自己成了那个人。灭火器还没造出来，卖砖头的可能已经卖了 100 个。

* **Personal agent 起来，更多可能是产品原因。** 单一的持久会话，拟人的形象。两个多小时的 AI 电影，明知是 AI 做的，弹幕都在讨论剧情。

## **嘉宾简介**

> 00:00:06--00:00:58

2025 年博士毕业后，他和苏煜（任 CEO）、Xiang Deng 一起创办了 NeoCognition。公司总部在 Palo Alto，做能在工作中持续学习、自行专精的 agent，2026 年 4 月以 4000 万美元种子轮亮相。节目录制时，他说公司是一家做 continual learning 的 NeoLab，很快会开始 A 轮，团队有 17 名全职员工和 4 名左右的实习生。他也是播客《不着边际》（Ungrounded）的联合发起人。（履历据公开资料整理）

## **第一部分 被模型进步打脸**

### **一、RSI：大模型公司的包袱，NeoLab 的机会**

> 00:00:58--00:04:35

**Koji** ：快年底了，我们最近在做一个系列内容，请朋友们分享这一年下来非常个人的经历：AI 给自己带来了哪些 aha moment，每个人分享 10 个。我提前看到你发给我的 10 个 aha moment，觉得和多数人的都很不一样。我们还是从第一个开始：第一个是什么？

**谷雨** ：RSI（递归自我改进）这件事。**上个月我还说，搞不懂为什么会有创业公司在做 RSI；最近发现我确实被打脸了** ，所以这是一个很大的 aha moment。我现在发现，startup 做 RSI 确实有它的一条逻辑。比如前阵子 Recursive 和 Mirendil 的发布，确实给了我很大的惊喜。

**Koji** ：这扭转了你的想法。

**谷雨** ：对，我发现他们还真的能做出来，还真的有这种机会。

**Koji** ：你原来觉得 startup 做 RSI 没有机会的原因是？

**谷雨** ：原来的逻辑非常粗暴。第一，做 RSI 本质上是模型叙事，你要追最前沿的模型厂。别说新的 startup，除了 OpenAI 和 Anthropic，其他模型厂这么长时间还在后面赶着呢，startup 上哪做？第二，RSI 是 recursive，你首先得有起点，起点得有自己的模型。这两点上我当时非常天真，觉得 startup 做这个不是很靠谱，但最近确实超出了我的想象。Recursive 和 Mirendil 的发布，比如 **Mirendil 有一个人搞了三个多月，训出的 pre-training model 比 K3 还要强** ，这些信息还是很刷新认知的。

**Koji** ：你觉得是什么原因，让他们在 NeoLab 的背景下也能做 RSI？

**谷雨** ：大家现在可能渐渐达成了一个共识：AI 的研发能力确实越来越强。你可以想象，总有一天它写 training infra、写 training recipe 的能力会超过人。当这一天到来的时候，**大模型公司之前积累下来的 infra 或 recipe，反而可能会成为一种累赘** 。

一个非常具体的例子：我在国内某家模型厂的一个朋友，前两周跟我聊天，说最近大家都知道 score centering 有用。他们也知道有用，用了可能会提一两个点，但为了用它需要去适配他们的 infra，代价太大，所以他们不愿意去做。但对一个从零开始的 startup 来说，就没有这种负担：反正都是 AI 去搜一套新的 recipe、搞一套新的 infra，我随时可以迭代它，随时可以丢掉它。

**Koji** ：所以因为还在不断变化，如果你的 infra、过去的一些 SOP 或者团队的组织架构已经成型了，你就比较难调整去适配新的变化。

**谷雨** ：是的是的。

**Koji** ：反而这个时候，NeoLab 有它的灵活性。

**谷雨** ：对，它可能会有更大的加速度。

**Koji** ：但前提是不是 NeoLab 还是得融到更多的钱，才能有资源、有卡、有数据？

**谷雨** ：那是因为你要走模型叙事，要做完整的、full stack 的模型训练，肯定需要大量的资源。所以 Recursive 和 Mirendil 确实拿了很多钱。

**Koji** ：除了这两家，你还看好谁？

**谷雨** ：包括 Jeff Dean 的 Discovery Loop，这种 RSI 公司可能都挺有机会。国内也有一些了，但可能可以再观察观察。

**Koji** ：这是第一个 aha moment，其实是你的认知被改变的一个时刻。

**谷雨** ：对，我觉得 aha moment 的意思就是这个：你感到惊讶，才会有「啊哈」。

### **二、Computer use：手基本解决了，难在脑子**

> 00:04:36--00:06:54

**Koji** ：那第二个是什么？

**谷雨** ：我们团队一直在做 computer use agent，今年确实发现，computer use agent 这件事快解决了，它真的泛化了。比如在去年，我们一直在聊 computer use 最大的问题是泛化性和可靠性。从去年年底到今年年初，大家发现了这个趋势：computer use 所谓操作层面的问题基本解决完了。很大的一个原因是 coding 的训练规模上去了，泛化到了很多软件操作或者网页操作。

具体来说，**现在可能到了「手」已经基本解决、下一步要解决 cognitive level，也就是认知层面、「脑子」层面的问题的阶段** ，这就是我们公司在做的事情。比如它如果知道一件事该怎么处理，对应到软件或网页的操作，它完全可以做对。但很多时候的难点在于，它不太知道一件事应该怎么处理，比如每个公司内部会有一套自己的业务流程，这个它可能不太清楚；但一旦它清楚了，在认知层面知道要怎么处理之后，它的操作是没有问题的。这是过去这一年我们对 computer use 认知的一个转变。

**Koji** ：所以这个认知层面已经不是 computer use 的范畴了。

**谷雨** ：其实是 orthogonal（正交）的。但它具体需要体现在和软件或网页的操作交互上：比如你要做数字世界的一些工作，最终还是要落到这上面。

**Koji** ：了解。所以这对你来说是一个 aha moment 的原因是什么？

**谷雨** ：因为我们公司刚成立的时候，花了几个月时间，一直想要解决操作层面的问题。

**Koji** ：当时你们的解题思路是？

**谷雨** ：当时操作层面有个很大的问题，就是所谓的 reliability：它可能做一次能做对，第二次可能会做错。所以我们当时的做法是让它做几次，把做对的那次挑出来，封装成一个 reusable 的 skill，为此搭了一套 pipeline。**但现在发现完全不需要，比如你让 Opus 5.5 自己去实现一下这个流程，其实很快** 。

**Koji** ：没错，而且如果有错，它会在这个过程中自己纠错。

### **三、Apprentice Bench：一百道题要连着做**

> 00:06:55--00:13:17

**Koji** ：要不要再讲一下你们在做的这个 Apprentice Bench？

**谷雨** ：我们公司做 continual learning，要真正去解决的是：agent 或者模型部署之后，在生产过程中怎么样持续地迭代自己。这件事现在并没有一个现成的 benchmark 能很好地去评估它，所以我们定义了这个 benchmark。它做的是建筑行业的会计场景。

**Koji** ：非常垂直，建筑行业的会计问题。

**谷雨** ：因为它很真实。

**Koji** ：有多少道题？

**谷雨** ：100 道题。

**Koji** ：这 100 道题是一个什么样的分布？

**谷雨** ：这 100 道题其实都在做一件事，就是会计报账。但每道题背后可能会涉及一些不同的规则，比如这个公司处理事情的一些不同的 convention、一些 specific 的 workflow、一些特别的审批流程，各个题目会包含这些。

但有一个很特别的点：我们这个任务和现在的很多 agent benchmark 有一个本质的不同，就是这 100 个任务不是独立的。现在的 benchmark 正常是一些独立的题目，我们这个你得连着做，in a stream，一个一个连着做 100 个。

**Koji** ：这么设计的原因是什么？

**谷雨** ：**这 100 道题连着做，是一个边干边学的过程** ：你做了前面的题目，从前面题目得到的反馈或者学到的知识，才能让你继续去做后面的。所以我们预期它是一个持续学习的过程，我们 evaluate 的其实是一个持续学习的故事。

这也涉及我们对 long horizon、也就是长程的看法。现在有很多 benchmark claim 自己是做 long-horizon agentic tasks 的，这些 benchmark 有个 bias：它们可能会去找一堆特别难的任务，一个 agent 或者一个人要做半天。但我们觉得这可能不是最理想的状态，有两点。一点是这种任务很难去找，你很难 scale up。另一点是：我们为什么要长程？我们对长程的预期是什么？

我个人认为，长程的终局是，如果你真的 scale up 起来，量变引起的质变是我们会得到一种所谓的 lifelong intelligence。而要 lifelong intelligence，一定不是光埋头在那边一直干一件事，而是得一直能够边干边学，持续迭代自己。打个比方，我们认为**真正的长程不是一个会计一个账给你报一个星期，而是一个会计从公司的菜鸟员工变成这个公司的老员工** ，这几个月或者一两年的过程，这才是真正的长程。这种长程 scale up 起来，才能到达所谓 lifelong 的 intelligence，就像人一样。

**Koji** ：我觉得这个非常 make sense。

**谷雨** ：对，这也是我们公司提供的一个新的视角，同时也是我们为什么要定义这个 benchmark：希望能告诉大家，未来应该去追求的方向是什么样的。

**Koji** ：现在这个 Apprentice Bench 刚发布对吧？你们之前发的 benchmark 可不可以介绍一下？

**谷雨** ：我们组之前在 OSU NLP 的 lab 发过一些很有影响力的 benchmark。比如 MMMU，一个多模态的 benchmark，OpenAI、Anthropic 和 Google 发模型的时候其实都会默认用。还有 agent 相关的 Mind2Web，我们做得非常早，是 23 年 5 月发的，算是 LLM 时代最早的 computer use 或者 web agent 的 benchmark；它后续的变体，比如 Online-Mind2Web，Anthropic、OpenAI、Gemini 发模型的时候也会使用。另外我们之前跟国内也有合作，比如和清华合作过 AgentBench。AgentBench 可能发模型时评估用得不是很多，但它确实算是最早期 LLM agent 时代的一个 evaluation，给大家提供了 agent 任务早期的 formulation，以及数据上和任务分布上的一些资源。

**Koji** ：我们再说回 Apprentice Bench。我觉得要在 Apprentice Bench 上把分数提上去，好像还挺难的。

**谷雨** ：目前的第一版，最强的模型，就是 Claude 最强的模型，已经做到 80 分左右。

**Koji** ：那要提分，要怎么提？

**谷雨** ：就是 continual learning 的能力。这一点是我们现在觉得非常区分前沿模型和非前沿模型的一个 dimension。

**Koji** ：什么样的数据能够在 continual learning 上帮它们有大的提升？

**谷雨** ：最重要的是能够让它更好地去写 memory notes 的数据。我听说 OpenAI 和 Anthropic 都有自己的一些 recipe，但有一种可能性是，比如 Claude 和 Codex 这种 long session，天然就会伴随这种性质的数据。但目前这个 recipe 我觉得并不是一个非常成熟的东西，我们公司其实也还在探索；除了那两家，其他的 model lab 在这方面也都没有做得特别好。包括那两家，虽然它们现在在我们的 benchmark 上分数也挺高，但我觉得还是有很大的提升空间。因为我们很快会发新的版本，目前最强的模型在新版本上分数也会低很多。

**Koji** ：我在想，其他 benchmark 都比较容易刷分，你们这个没有那么容易刷，因为要做一套配套的 data set，难度好像要大一点，会这样吗？

**谷雨** ：刷分有两点。第一，我们没有公开，所以厂商没有办法追着我们刷。第二，这跟 benchmark 本身定义的 challenge 有关系。你光对着我们 benchmark 的数据本身去解，没有意义：你让你的模型把针对这个公司特定规则的会计报表做好，有什么意义呢？刷这个对模型没有任何好处，因为我们测的并不是这种 level 的能力，**我们测的是 meta level 的能力，是更元级别的能力，就是持续学习能力** ；只是持续学习能力做好了，它可以体现在这上面。所以你就算要去刷，有意义的刷法也应该是去刷这种 meta level 的能力。你要真能把它刷上去，那我也服了，那也算积德了。

### **四、数学：不得不信 scaling**

> 00:13:18--00:14:30

**Koji** ：好，这是前两个 aha moment。第三个是？

**谷雨** ：最近的数学。大家都知道，千禧年问题都开始被 OpenAI 一个接一个地解决了。这个 aha moment 可能更多是去年的，直到今年进一步，就更「啊哈」了。

**Koji** ：放大了 50 倍、100 倍。

**谷雨** ：24 年那个时候，大家包括我自己，都觉得数学能做成是因为你有 formal verification，有 Lean 这种形式化的系统。结果后来发现，**你的数据量上去、质量上去，去年就已经可以通过 informal 的方式拿到 IMO 的金牌了** 。那个时候其实已经很好了，但没想到今年更进一步：千禧年问题，可能后面基本上用 informal 的方式就可以把这些问题都解决。这确实至少打破了两年前的认知。两年前那会觉得，你需要有 formal 的形式化系统来给你 signal，不然纯 informal、靠 LLM 来 judge 自己，有点左脚踩右脚的感觉，那会觉得这件事的上限可能不会特别高。但发现确实还是认知不足。

**Koji** ：还是某种 bitter lesson，**我们还是应该相信 scaling 可以解决更多的问题** 。

**谷雨** ：不得不信，现在不得不信。

### **五、Memory notes：又被打脸一次**

> 00:16:23--00:18:02

**Koji** ：第四个是什么？

**谷雨** ：第四个可能又回到跟我们公司比较相关的 continual learning。这其实也是很打我脸的一件事。今年上半年，我还在到处 talk，说基于 memory notes、也就是写 memory notes 这种方式来做，肯定是不靠谱的。当然观点也很 research：你通过 rewrite memory notes 这种方式，它并不是一个 reliable 的 optimization algorithm，所以我觉得它就是不行。结果发现人家 scaling，或者继续训，它还是能行。一个是 computer use 到了临界点，我们刚才提过；另外一个就是，**基于 memory notes 做 continual learning 这件事的上限被我们低估了** 。

## **第三部分 创业这一年**

### **十一、灭火器与砖头**

> 00:25:40--00:29:54

**Koji** ：我们刚才在说创业，那创业到现在有快小一年的时间了，感受怎么样？和你一开始的预期是一样的吗？你想要的自由、自主，这些都拿到了吗？

**谷雨** ：这其实也是一个 aha moment。我们到第几个了？

**Koji** ：刚才聊完了 6 个。

**谷雨** ：那这是第七个，我觉得也挺有意思。我们整个团队，在我的导师苏煜老师带领下，之前在学校的时候，整个组的口碑、reputation 还是挺好的。很大程度上是大家觉得我们的 vision、我们的 taste 不错。这是什么呢？学术界有一个非常典型、很多人会犯的问题，就是拿锤子找钉子：我先去想一个算法，或者想一个奇奇怪怪的设计，再想办法看它能用到什么问题上，然后写一篇 paper。这种事我们从来不干，我们会真的去比较本质地想这个技术问题到底有什么 fundamental 的 issue，然后从更 fundamental 的角度去解决问题。我们在学术界一直是这样的风格，这也是为什么我们在 LLM agent 的时代做了一些开创性的工作。

但**放到创业上之后，我发现，我们成了那个拿锤子找钉子的人** ，或者所谓 solutions in search of problems（SISP）的人。原因是，做学术研究，你只要在一套技术体系内能闭环、能自洽就行，你有一套完整的 system。但**做 startup，光自洽不行，光自洽是自娱自乐** 。你需要和 market 一起完成闭环，还得想这些 fundamental problem 能解决别人的什么问题，能带来什么样的 business value。

**Koji** ：商业价值。

**谷雨** ：对。这就是我们过去可能几个月或者一年时间在交的学费。我们可能一直还是从根本的技术问题出发，它确实是现在 AI 的一个 fundamental problem，但你要把它放到 market 里、放到产品里，它应该是什么样的形式？应该去解决什么样的问题？这确实是过去我们交的学费。

**Koji** ：很多时候道理都懂，但自己做的时候才发现，纸上得来终觉浅。你在讲的好像是一个挺浅的道理，就是做公司要考虑怎么赚钱；但如果不是自己做，别人直接告诉你，你是没有那么深刻的体感的。

**谷雨** ：是，我觉得说了跟没说一样。但做起来确实是，一旦进入做事的状态，你可能会局限在自己的 bias 里面跳不出来。所以人要经常跳出来反思一下自己，可能会帮自己去完成迭代。

有一个例子我还挺想讲。VC 有一个理论：当一个人头上着火了，他是不会等着你给他一盆水或者一个灭火器的，他手头有个砖头，也得把头上的火给拍灭。这是什么意思？我们这个学术团队出来，做事很 solid，一直在想，OK，我们要造出一个好的灭火器。但**可能在你的灭火器造出来之前，别人卖砖头的已经卖了 100 个** 。

**Koji** ：这个具体投射到你们的业务上是什么？灭火器和砖头分别对应什么？

**谷雨** ：**我们对于发布的标准太高了** 。我们总是要 release 一个自己觉得特别满意、特别 solid 的东西。但作为一个公司，你有时候可能真的 maybe 先发布一些不那么成熟的东西，先把闭环跑起来，甚至有时候先把牛吹出去都行。但我们这方面确实太本分了。

**Koji** ：在这方面有谁做得是你觉得足够好的吗？因为你肯定不能 bluff，或者说了之后 deliver 不了。但这里面节奏的把握其实还是重要的：你说得早，你会成为第一个 momentum 的创造者，后面会有很多的红利；当然最后你要不断地 deliver。

**谷雨** ：最典型的就是马斯克。我觉得马斯克就是硅谷这种 fake it till you make it 的极致。

**Koji** ：你是可以沉浸式地看进去的。

**谷雨** ：是真的可以看。

**Koji** ：你并不是说「我来了解一下 AI 今天能做到什么程度」，而是真的把它当作一个故事、一个电影在看。

**谷雨** ：我是真的把它当电影看。我觉得对于影视从业者来说，这可能是一个更大的 aha moment。

**Koji** ：那看的时候，弹幕上会飘什么？会有对 AI 的讨论吗？还是几乎都已经在讨论剧情，不讨论 AI 了？

**谷雨** ：都在讨论剧情。我觉得这件事确实也挺好的。

**Koji** ：但看的人都知道这是 AI 做的吗？

**谷雨** ：都知道，因为 B 站会声明 AI 创作。

**Koji** ：所以大家知道这是 AI 做的，可是也不 care 它是不是 AI 做的，大家 care 的已经是这个电影做得怎么样了。

**谷雨** ：对，我觉得**最终大家对于一件事是怎么产生的，可能不是很在意，关键还是最后的 deliverable 长什么样** 。

**Koji** ：那你有产生过自己去做一下的这种冲动吗？

**谷雨** ：我觉得其实还挺想试一试的。这个时代真的很利好创作者，就像 Alex Wang 说的，大家都可以去 dream，大家想做的事情，现在 AI 能帮你去实现。

**Koji** ：说到这里，我突然想到，我有一个好朋友前两天写了一部科幻小说，idea 是他的，写作上 AI 帮了很大的忙。它背后的主题是什么呢？在未来，算力会越来越贵，人则变成了永生。那个时候，如果你想获得更多的算力来享受生活------因为你要娱乐------你要用什么去换呢？用你的记忆去换。因为记忆是数据，模型还在进化，那时候的进化仍然需要吃掉人更多的记忆、更多的数据。所以那个剧情其实是一个很悲伤的故事：人在卖掉自己的记忆，去获得更多的算力来享受当下的生活。

**谷雨** ：关于怎么样更好地做记忆这件事，可以关注 NeoCognition 后续的工作。

**Koji** ：这个植入也太丝滑了。

### **十四、Personal Agent 真的有用**

> 00:36:31--00:38:52

**Koji** ：好，我们来说最后一个 aha moment。

**谷雨** ：Personal agent 这件事突然起来了。为什么起来了？它确实不是说技术真的到了什么临界点，当然这和技术进步肯定有关系：比如 coding 更强，能做更多的事情；computer use 更强，在后台操作软件、操作网页的能力确实更强。但**我们感觉更多可能还是产品上的原因** ，有两个很关键的设计。

第一，**你要真的做成一个 personal 的 assistant，像 ChatGPT 或者 Claude 那种 session-based 的会话管理肯定是不合适的** 。如果你把它想象成你的助手，你不可能说一件事开一个窗口、说一件事开一个窗口，而是得有一个 persistent 的单独会话，比如你现在跟 Muse，就是一个单独的会话，从头到尾。因为这样就有人的感觉，就像你在微信上跟人聊天：每一个对象是一个窗口，你不会今天让他做这件事开一个窗口，明天让他做那件事再开一个窗口。

第二，还是产品层面，你要让它更有人的感觉。这也是为什么这些 personal agent 都要搞一些卡通的形象，我觉得是为了进一步增强这种感觉。比如 Muse 那个毛绒形象，做各种各样的 PR，这确实是一定程度上的拟人化。

另外，大家在说 proactivity，我觉得 **proactivity 本身也不是什么特别新的技术** 。年初 OpenClaw 就有这个 feature，包括 ChatGPT、Claude 的 scheduled task，你一样能做到：固定时间去看一下邮件，给我个推送，都能做到。所以我觉得本质上还是产品跟交互体验。

**Koji** ：你自己在用什么？

**谷雨** ：我自己在用 Muse 和 Instinct。

**Koji** ：你要用两个，它们俩你要怎么分工？

**谷雨** ：其实都是在帮我看看邮件、看看消息。因为在国内的话，这种服务平台你用不了，比如外卖、订酒店、订机票，这些都不太好用，所以其实主要就是让我看邮件。但看邮件这件事还挺关键的，因为邮件很多，它真的能帮你挑出一些需要 prioritize 的重点邮件，然后自己推送给你。这一点确实还挺有用的。

**Koji** ：你觉得最后会收敛到只用一个吗？

**谷雨** ：最终确实吧。可能现在我之所以在试不同的，其实很大程度上也只是尝鲜而已。但真的当我生活中形成这种依赖之后，我觉得只要一个就够了。

## **结语 明年**

> 00:38:53--00:40:50

**Koji** ：今天的十个 aha moment 都说完了。最后来预测一下明年吧：说到明年，你觉得有什么一定会发生的事吗？

**谷雨** ：明年一定会发生的事......我们公司被高价收购了。开玩笑，开玩笑。明年一定会发生的事：明年我会再老一岁。

**Koji** ：这是一定会发生的。AI 不能让时光倒流。

**谷雨** ：对，但是 AI 有可能会研制出长生不老的药，不过这可能不是明年的事。

明年，我觉得对于模型的发展来说，可能每一年都会有一个关键词，这对大家的职业规划可能会有一定参考意义。比如 24\~25 年，那会你做 vision language、做 VL、做 multimodal；25 年年底到 26 年做 coding；**26 年这个时候到明年，我觉得你得做 continual learning** 。这可能是明年，起码到明年下半年之前的一个关键词。

我想想还有什么关于明年的预测......其实还挺难的，因为在这个时代，我觉得一年这个跨度已经非常长了，毕竟现在模型迭代都是以周为单位的。Maybe 可能明年------这个我瞎预测，不是说我觉得一定会发生------**真的会有一个来自 RSI 公司的最强模型** 。

**Koji** ：RSI 的创业公司的最强模型。

**谷雨** ：或者至少是前沿的一个模型。

**Koji** ：SOTA 级别的。我们拭目以待吧。
