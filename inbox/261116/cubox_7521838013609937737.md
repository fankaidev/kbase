# 如何比99%的人更擅长使用Grok Bot？丨Greg Isenberg

"我现在很少自己打开网页了，除非像刷 X 那样，我确实想亲自去看。"  

"我宁愿先把设计定下来，自己看着满意了，再让它写代码。"  

"我通常不用 AI 写脚本，因为我发现，人还是更爱听人讲。"

Ras Mic 想给自己的产品 Pluto 加一个功能，让用户能用自己的数据微调模型。朋友用 Claude Code 写了方案，发来一份 PDF。Mic 把文件转给 Grok Bot，只让它先看看方案哪里有问题。接下来，他补了一条必须满足的要求，又把朋友的反馈贴进去。等改好的方案过了自己这一关，他才让机器人叫 Claude Code 开工。几个小时后，聊天里多了五个可以审查的代码改动。

在这场访谈里，Mic 打开自己的 Grok Bot，翻给观众看的大多是这种还在推进的事。有的到了测试阶段，有的隔夜生成了代码，他甚至还没跑过。这些机器人分工不同，有的每天替他找选题，有的记着项目上次做到哪儿，还有一个专门劝他别乱花钱。

## 哪些项目值得养一个专用机器人

Mic 在 Grok Bot 里给 Pluto、自己的圣经应用和 Bezalel 分别建了机器人，每个都有自己的项目资料、技能和工作环境。Bezalel 当时每月有约 200 美元的经常性收入，Mic 已经把它当作一个需要长期维护的产品。拿 Bezalel 来说，他有次想找之前让 AI 做过的首页动画，连参考图是什么样都忘了，只说了句「那个带动画的东西」。机器人起初找错了改动，经他提醒才认出是个拖拽演示，并问要不要把它做成首页原型。Mic 让它继续，看到成品用了通用图标，又要求换成相应公司的标志，最后亲手合并了改动。

要不要单独建一个机器人，取决于这个项目以后还会不会反复用到同一批资料和决定。 他的通用工程机器人负责接零散点子，比如一个叫 Still 的截图扩展，据他说前后只用了两轮指令。一次朋友和他聊美国政府采购，他让机器人看看有没有跟 AI 治理相关的招标，又让工程机器人试着做个合规工具。第二天 GitHub 上已经有仓库，但录节目时他还没亲自运行，所以能确认的只是做出了代码。

反过来，要经常维护机器、下载和微调本地模型的工作，他分别留了长期使用的 IT 和机器学习机器人。节目里他当场删了一个做多伦多课程相关工作的机器人，理由很简单，那件事已经结束了。投资终端、交易平台这些实验是不是值得长期占个位置，他自己也还在看。

## 先审方案，再让 Claude Code 开工

回到 Pluto 的微调功能。Mic 给 Grok Bot 的材料不只是一份 PDF，还有朋友的意见、他自己认定不能省掉的要求，以及一条供参考的推文。等它根据这些材料修完方案，他才下达实现指令，让 Grok Bot 用 Claude Code 的 Opus 5.5 和 \`/goal\` 开工，需要时开多个会话，把改动放在独立的工作目录里，最后通过 PR 交给他审。截图里的执行计划还专门保留了几道关口，合并代码、改生产环境和启用付费资源，都要等他点头。Mic 说五个 PR 已经齐了，有人在测试这个功能。

"我当时只说「审一下」，没让它上来就做。"

Mic 把开会话、分任务和收结果交给机器人，自己保留方案审批和合并代码的决定。 他也用 Codex 和 T3 Code。接 Claude Code 时，可以在机器人使用的机器上登录，也可以像他那样，用 Tailscale 把自己的机器连起来，由机器人调度已有的开发环境。Greg 问他何必多加一层，他举了个很日常的例子：在妈妈家吃饭时，手机上就能看到跑完的改动，知道哪个项目需要他看一眼。至于为什么这次选 Claude Code，他提到模型偏好和订阅成本，他把每月 200 美元的订阅折算成按 API 调用计费约 8,000 到 12,000 美元的用量，这是他在节目里给出的估算，不能当作套餐额度。

这种分工也用到了代码之外。为在加拿大提供本地算力的 VP Cloud 找供应商时，Mic 说其中一个机器人让另一个机器人去发邮件询价，主动把他的 YouTube 订阅人数写进邮件，当作谈折扣的筹码。节目没交代折扣有没有谈成。真正出乎他意料的是，他没叫机器人拿频道说事，机器人自己想到了。

同一段里，Mic 还展示了受彭博终端启发、用 Rust 做的交易工具，说它可以接券商并切换到实盘模式。另一个用加密资产交易合成股票的点子，当时已经有代码，他还在找托管服务。Greg 接着问，做得这么快，安全怎么查？Mic 说，他会让本地模型反复检查 Pluto 一类应用，也区分了不同产品的风险。他做的圣经应用免费、无需登录，涉及收款或敏感信息的应用，在他看来更需要认真检查。他讲的是自己的做法，节目里没有公开检查结果。

Mic 在 Grok Bot 里交代 Pluto 的实现方式，要求用 Claude Code，允许开多个会话。

## 网店先在画布上改，满意了才写代码

给弟弟的服装品牌做网店时，Mic 把服装素材发给机器人，想要带基督教元素的哥特风格。机器人起初按 Framer 想方案，他纠正说网站要放在 Shopify。接着，他让机器人通过 MCP 在设计工具 Paper 里画页面。Mic 平时会从 X 和 Mobbin 找参考，拿一张喜欢的截图，让机器人提炼成一套可以反复用的设计规范，再自己改字体、颜色、间距和按钮大小。这样换页面或做新组件时，机器人有一套现成的规则可循。

"我可以在 Paper 里留评论，然后让机器人去处理这些评论。"

字体、排版和页面内容先在设计稿上定下来，改完再接到 Shopify，能省掉一轮重写。 Mic 演示了怎么在画布上标出不满意的标志、字体或间距，然后让机器人按评论改。他接入 Shopify 账号后，让机器人把定下来的设计做成店铺前端，并在节目里打开页面展示。

服装店首页进入 Shopify 编辑器，页面沿用了在 Paper 里定下的设计。

## 每天两次找选题，脚本还是自己写

早上九点和下午五点，Mic 的 YouTube 机器人各扫一遍 X，每次发来三个适合他频道的题目，附上原帖、标题提议和可用资料。节目当天，他点开了几条候选，其中有 Claude 接入金融服务，也有远程编程智能体。连数据中心的地方投票，机器人都能从科技从业者关注的角度挑出来。Mic 说这些题目不会照单全收，但每天都能看到这一行的人在聊什么，自己拍视频时手边也有资料。

选题机器人替他找材料，他自己决定这件事值不值得拍、该怎么讲。 他还有一个剪辑机器人，专门用来试风格。以前看粗剪只会说「这段有点黄」，说不清要调什么，现在可以先用自己的话描述想法，再把整理好的要求交给真人剪辑师，让对方按实际画面调整。录制时，他还没有用这套剪辑流程发过成片。

Greg 则讲了自己的试验。他想到一个题就用手机录一段，把素材和剪辑要求交给 Claude Code，出来的短视频直接发过，其中有几条据他说有几十万播放。Mic 也试过让 AI 做动画，觉得难点已经变成怎么把节奏、字幕和动画该怎么进场讲清楚。

## 顾问机器人拿他的账本劝他别买楼

Mic 说自己很容易突然对新生意来劲，今天想开卡车运输公司，明天又去看投资房。他把一条房产挂牌发给顾问机器人，得到的答复是现在先别买。这栋楼会占用他为别的目标留的现金，卖家还只接受没有代理人的买家，锅炉和暖气设备则是 2009 年的，未来几年可能要预留更换费用。这些都是机器人根据挂牌和他的情况指出的疑点，节目没有逐项核实房况。

让这次劝阻有针对性的，是顾问知道他正为什么存钱，也能看到他的钱花到了哪里。 Mic 说他通过 Plaid 接入账户，让财务机器人分别处理个人和公司相关的资料。他也试着让机器人筛加拿大的政府合同，结合自己公司的情况判断哪些值得看、哪些得先招人。同样的上下文也能用回设计。有次他要给朋友做网站，机器人主动问要不要复用之前为亲友项目做过的 Paper 设计规范，免去他重新找一遍。

这种用法依赖财务和业务资料的访问权限。节目里 Mic 特意没有往上翻涉及具体金额的聊天记录，观众能看到的是顾问怎么把目标和挂牌细节摆到一起，至于账户里具体有什么、机器人拥有哪些交易权限，访谈没有展开。

## 买 PS5 Pro 时，他自己打了最后一通电话

Mic 让购物机器人每天在 eBay 上找未拆封的显卡，看到合适的就发给他。有次他想买一台 PS5 Pro，机器人先给卖家发邮件，查出对方是安大略省一家离他约两小时车程的店，接着把电话号码和一份通话提纲发给他。他没照稿念，自己打电话确认后才给机器人下单权限。另一次他想找穿着舒服的鞋，让机器人列了几双、发邮件请妻子帮挑，再把她选中的款式转回来。

购物里最省事的一步，是机器人把候选和待核实的问题都找齐，他只需要确认那件自己在意的事。 对 Mic 来说，这就是他现在少开网页的原因。节目末尾，他还拿出桌上的树莓派和音箱，讲自己没做过硬件，遇到不知道怎么接线、要买哪块配件，就边问边装。两三年前他还在上班，做 YouTube 只是图个乐，当时 Greg 第一次私信他，他甚至以为是诈骗，特意确认了才回。如今他在节目末尾拿着手边的硬件说，有些以前只在脑子里想过的事，现在可以动手试了。

## 写在最后

手头有一件总被打断的小事，就可以从那里试起。 比如每周收集选题，先让 AI 把原帖和资料找齐，你来挑哪条值得跟。做几次以后，再看看它有没有记住上回为什么淘汰某个候选，下回能不能少走一次弯路。这个变化比一天建了多少机器人更容易看出来。
